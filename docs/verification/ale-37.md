# ALE-37: browse and explain Gemini CLI skills

`--agent gemini` adds Gemini CLI discovery to the shared collection snapshot and terminal availability presentation. `list`, `read`, `explain`, `problems`, availability filters and `browse` share one calculation. Every writer remains unsupported. Production discovery reads bounded local files, without starting Gemini, evaluating `.env`, connecting to a service or executing skills, extensions or hooks.

## Validated native contract

Reference release: **Gemini CLI 0.63.0**, installed temporarily with `npm install --prefix /private/tmp/ale-37-native --ignore-scripts --no-audit --no-fund @google/gemini-cli@0.63.0`. Nothing was installed globally or into live user configuration. `tools/verify_gemini.py PACKAGE_DIRECTORY ARTIFACT_DIRECTORY` runs the real package's `--version` and `skills list --all` under a macOS sandbox that denies every network operation, with a fresh credential-free environment and inert fixtures outside all Git checkouts. It never submits a prompt or activates a skill. The actual bundle SHA-256, Node version, arguments, exit codes and native output appear in `ARTIFACT_DIRECTORY/receipt.json` and its adjacent text artifacts. See [Repair verification](#repair-verification) for the native helper's containment policy and runtime gaps.

The recorded native discovery census covers: version; workspace alias winner; untrusted user alias winner; no workspace ancestor inheritance; case-insensitive union of disabled names; workspace scalar override; insecure system-settings rejection; root and child manifests, name sanitation and shared aliases; registered extension versus orphan folder; inactive extension exclusion; last matching extension override; persisted trust; persisted distrust; configured `GEMINI_CLI_HOME`.

Native roots are `HOME/.gemini/skills` and `HOME/.agents/skills`, or the corresponding locations under `GEMINI_CLI_HOME`. A selected workspace adds exactly `WORKSPACE/.gemini/skills` and `WORKSPACE/.agents/skills`. Git markers do not alter Gemini discovery. Omitting `--project` adds no workspace roots, regardless of the viewer's working directory. Extra viewer roots are inspection-only; they do not invent native runtime search paths. Gemini discovers `SKILL.md` at a root and one directory below it, including both when a root manifest exists. Hidden folders, `node_modules` and deeper containers do not participate. Generic explicit-root behavior is unchanged.

Native precedence is built-in < extension < user `.gemini` < user `.agents` < workspace `.gemini` < workspace `.agents`. Names remain case-sensitive for conflicts. Disabled-name matching is case-insensitive. Definitions are selected before disabled-name filtering, so disabling a winning name does not restore a lower definition. Different copies retain separate source IDs, related-source links and the winning source ID. Several references to one proven directory remain one shared source. Ordering among independent same-name definitions within one tier is unspecified and yields unknown, rather than a guessed winner. A potentially competing native manifest whose name cannot be inspected also makes affected precedence unknown; a lower-tier definition is not asserted as the winner merely because the higher-tier input exceeded a viewer limit.

The native loader requires frontmatter on the first line and both name and description fields. Its native simple-field fallback and punctuation sanitation are represented separately from generic manifest diagnostics. Names replace `:`, backslash, slash, `<`, `>`, `*`, `?`, double quote and `|` with `-`. A manifest file symlink remains acceptable to this version. Unverified environment-expanded native names remain unknown.

## Settings and trust

Relevant JSONC settings are read as system defaults < user < trusted selected workspace < system overrides. Scalars use the last layer; `skills.disabled` arrays are unioned. An empty workspace disabled list does not re-enable a user-disabled name. `skills.enabled=false` disables the subsystem. Permission explanations retain each layer and only relevant selectors, without exposing unrelated settings or credentials. Invalid types, malformed, oversized, unreadable, nonregular or broken-link native inputs make calculated permission unknown and coverage incomplete. Unverified `$VAR` or `${VAR}` names in `skills.disabled` have the same effect.

System files default to `/Library/Application Support/GeminiCli/system-defaults.json` and `settings.json` on macOS. `GEMINI_CLI_SYSTEM_DEFAULTS_PATH` and `GEMINI_CLI_SYSTEM_SETTINGS_PATH` select alternate native inputs. Gemini requires root ownership, no group/other writes and securely owned symlinks on the file, all lexical parents and resolved parents. Insecure inputs are visibly ignored. The disposable native fixture proves this rejection. Secure root-owned system scalar precedence is verified from pinned official source, not from a native privileged fixture. No ownership or permissions on the user's machine were modified for validation.

Workspace settings admission and final skill participation are separate trust evaluations. Initial settings, including system overrides, determine whether workspace settings are admitted; trust is then recalculated from the final merged settings without retracting admitted permission choices. `GEMINI_RESTRICTED_MODE=true` takes priority and excludes workspace skills, followed by `GEMINI_CLI_TRUST_WORKSPACE=false`; otherwise `GEMINI_CLI_TRUST_WORKSPACE=true` or the effective `security.folderTrust.enabled=false` permits them. Explanations identify the controlling environment variable or settings file. Otherwise `.gemini/trustedFolders.json`, or `GEMINI_CLI_TRUSTED_FOLDERS_PATH`, supplies `TRUST_FOLDER`, `TRUST_PARENT` and `DO_NOT_TRUST` choices. Canonical containment determines matches; specificity uses the normalized logical rule key's UTF-16 length, not its resolved target's length. Trust keys are case-insensitive on macOS and Windows. The first equal-length matching key wins; normalized-key collisions keep the last value at the original insertion position. Relative keys remain unknown because the native working directory is not inspected. An absent choice excludes workspace skills until trust is established. IDE trust is not inspected. Workspace settings rejected at admission are reported as ignored; definitively untrusted bundles remain browsable as unavailable.

## Extensions, consent and limits

Extension candidates are bounded to `.gemini/extensions/*/skills`. Eligibility requires a valid `gemini-extension.json` with native name/version registration. A folder or cache alone is unavailable. `extension-enablement.json` overrides are evaluated in order against the selected workspace; the last matching rule wins, including `!/*` and exact project re-enablement. Inactive registrations are unavailable. An absent enablement registry retains default enablement; existing entries with missing or wrongly typed override arrays or non-string elements are unknown. Uninspected registration manifests remain unknown rather than proving native rejection. Linked extension install sources are inspectable, but native activation of linked installations remains unverified. Duplicate extension registrations, active extension allow/block security policy after final settings precedence, and environment-expanded names remain unknown. Project-specific extension overrides without a selected workspace remain unknown. Registered plugin provenance identifies name and version, while canonical directory containment determines managed content ownership; a reference escaping a managed directory does not grant ownership to its target. A directory registration alias can participate natively while its external target retains unknown ownership. Managed extension containment must remain inside the canonical native extension registry.

Ordinary eligible skills are **ask**, because native `activate_skill` normally asks for consent. Built-in skills are pre-approved and may be available. Built-in roots are recognized only when a local `gemini` executable resolves beside its `builtin` bundle directory. Other packaging layouts remain unverified. The probe observes built-in listing; consent behavior is verified from native source, without activation. Viewer filters do not convert consent into enablement. Policy overrides, approval modes, IDE decisions, remote admin restrictions and already activated running-session state are not observed, so those gaps and session/reload unknowns remain explicit. The viewer does not claim that a local calculation proves model-session behavior.

Enable, disable, project-override and delete capabilities stay unsupported. Native name-level controls cannot isolate independent copies. Managed content and whole-extension control require their native manager; this browsing slice supplies no mutation interface.

## Repair verification

The pinned native parser consumes nonempty space/tab-indented lines following a description before scanning another field. The native fallback now follows that continuation rule, including CRLF input. A later top-level name, or an indented name after a blank/whitespace/nonindented termination, remains a field. Generic YAML parsing, malformed diagnostics, raw manifest bytes and diagnostic exit status remain independent of native name matching. Public list/explain tests and actual 48/80-column browser cells cover the malformed disabled-name journey.

The [ALE-23 containment record](ale-23.md#runtime-containment-boundary) owns the ordinary executable launch policy and its modeled-absent system-input limits. Production discovery defaults stay native.

The repaired native helper denies network operations and filesystem writes outside its canonical disposable fixture. `/dev/null` is an explicit nonpersistent runtime sink exception. Reads permit only the fixture, canonical package, exact Node executable, required OS libraries/devices, literal root directory required by dyld, and exact ancestor metadata required by Node path resolution. Parent code owns evidence files. Public-helper inert parent/child tests cover positive fixture writes, denied outside writes and modeled-home reads, symlink escapes and loopback networking. Sandbox failures stop the helper before later commands.

A bounded fresh 0.63.0 version/list smoke validates this contained launch policy after those inert controls pass. The earlier native discovery census and captured malformed-frontmatter oracle remain the semantic evidence for that repair; subsequent full-helper invocations and their exact case inventories are recorded separately in their receipts. The current full helper also records a contained Node-version invocation. Listing can initialize disposable installation/project/history/session-log state. It submits no inference workload, activates no skill or plugin, and observes no existing running session. Secure administrative settings and session behavior retain the earlier explicit gaps. Historical effects of the original helper outside its fixture remain unknown. Receipts retain helper/profile/runtime/package provenance, per-invocation hashes, exact arguments/environment/exits and, for subsequent helper use, fixture digests before and after commands.
