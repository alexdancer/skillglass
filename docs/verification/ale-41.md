# ALE-41 permanent deletion

## Shared behavior

`Snapshot.PreviewDelete`, `DeletePreview.View`, and one-use `DeletePreview.Apply` supply the ordinary `delete` command and browser reader's `X` action. Deletion is separate from settings controls. CodeAF participates in consumer discovery even though its application-specific controls remain unsupported.

The target is one proven source object and its canonical path. Directory aliases remain links after canonical content removal. Manifest-only links belong to their enclosing independent directory. Interior links are unlinked without traversing external targets. Equal names, equal bytes, and shared manifest objects do not merge independent bundle directories. A standalone Pi Markdown source removes only its canonical regular file. Multiple links to a standalone file refuse deletion. Internal hardlinks are disclosed and may be unlinked without changing their external aliases. Verified own-unlink changes advance the expected link count and change stamp for remaining names of the same inode, including hardlinked symlinks. The other metadata and ACL evidence must match, and held regular-file bytes must still match the sealed digest before another alias can be removed. This operation does not promise physical byte erasure.

The preview shows every selected-scope reference and seven native observations. Each observation retains its selected project, native environment overrides, searched roots, coverage, native references, availability, and provenance. Custom-only inspection references stay in the selected-scope section and are sealed without becoming native affected-consumer counts. Adapter-proven disabled, shadowed, unknown, and inactive native routes remain visible. Zero exact matches differ from discovery failure. Discovery covers those roots and the selected project, not other projects or the whole machine. Unrelated inaccessible search roots and siblings remain visible and sealed with their actual diagnostic paths. Aggregate root incompleteness alone does not establish target relevance. Ambiguous manager evidence or inaccessible scope relevant to the selected target refuses deletion.

Manifest dependencies are separate impact facts, not exact-source references. Each retains the independent SourceID, manifest path and resolution, removal boundary, references, and native provenance. Resolution through a selected directory or standalone file is disclosed in JSON and both terminal previews, including intermediate links inside the selected bundle. Equal bytes or a hardlink reached through a surviving external name do not establish a dependency. These facts are sealed and revalidated; dependent bundles, links, and settings are left untouched.

## Ownership and boundary policy

Deletion derives its own positive local ownership evidence. Generic discovery's unknown ownership does not grant deletion permission. The effective UID must own the target, all entries, and the actual boundary parent. Canonical ancestors may include trusted root-owned directories. Shared sticky temporary ancestors are allowed only above a private UID-owned anchor. Group or world writable tree entries and boundary parents refuse deletion. Bounded Darwin ACL inspection accepts understood deny rules and read-only grants. Any mutation grant, including a grant to the owner, refuses deletion. Unknown ACL layouts, flags, or rights also refuse. Exact ACL evidence participates in consent, including on ancestors. Symlink inspection reads the link object's ACL, not its external target's ACL. Unreadable metadata, immutable or append flags, special entries, and device crossings refuse deletion.

All native manager evidence takes precedence over a custom path or alias. A shared typed evidence seam retains whole Codex cache versions, Claude installations/local sources, Gemini installations, and CodeAF registrations independently of loader roots and activation. It also retains Hermes plugin storage/installations, Pi managed storage and registered local resource boundaries, and OpenCode's whole-cache ownership boundary. Local Pi package registration does not claim ownership of unrelated package files or external resource targets. Shared preflight checks boundaries by object ancestry, including undeclared installation siblings and case aliases; a skill link alone does not transfer ownership of external content. Relations distinguish proven containment/non-overlap from unresolved inspection. An inaccessible or cyclic registered alias cannot establish non-overlap: unresolved manager, native protected-root, home/project, and independent-source relations refuse deletion. Known absent unrelated boundaries remain non-overlapping. Arbitrary discovery diagnostics and custom search roots require proven relevance rather than turning inspection errors into global ownership refusal.

Manager input evidence distinguishes healthy absence, observed supported input, known boundaries, and uncertainty. Pi global and selected-project settings, each registered package manifest, Claude marketplace registrations, and each local marketplace manifest carry explicit reader identities and terminal coverage alongside parsed records. Shared preflight refuses missing required reader results. A successful byte read does not establish schema completeness. Partial records retain recovered boundaries plus uncertainty. Invalid registration fields with a known Pi package location bound uncertainty to that package; unreadable settings or unrecoverable locations remain unbounded. Unreadable or invalid local manifests bound uncertainty to the known package or marketplace, without claiming unrelated local package files are definitely managed. Activation-only trust, permission and resource-filter uncertainty remains separate. Unreadable, oversized, malformed, null, or unsupported installation registries fail closed when arbitrary external installations cannot be bounded. Bounded uncertainty refuses overlapping targets without blocking unrelated content. Registry observations and input bindings/bytes participate in consent. One deletion-scoped observer seals every native ConfigLayers and manager input path, plus a distinct resolved endpoint when linked. It retains endpoint identity, bounded full bytes, metadata and ancestor bindings; unreadable, dangling or cyclic relevant endpoints cannot grant consent. Healthy optional absence remains supported. Both endpoint-byte changes and same-byte endpoint replacement invalidate old consent without changing settings. Diagnostic wording, arbitrary path names, loader roots, and availability ownership labels are not substitutes for this evidence. The filesystem root, home, selected project, application homes, semantic native collection roots, manager boundaries, their ancestors, and a target enclosing another independent source refuse deletion. A custom discovery root that is exactly one ordinary manifest-bearing bundle may pass. Boundary checks reuse proven object ancestry, including case aliases on case-insensitive filesystems. Child directory manifests establish additional bundle boundaries without following links.

The exact inventory includes hidden entries, names, object identities, ownership, modes, flags, exact ACL evidence, change stamps, regular-file SHA256 digests, and symlink text. It refuses instead of truncating at these bounds:

- 10,000 entries, including the selected root.
- Depth 128 below the selected root.
- 256 MiB per regular file.
- 1 GiB of aggregate hashed regular-file bytes.

These checks establish local filesystem control and absence of known manager ownership within bounded discovery. They do not prove intellectual-property ownership.

## Consent and removal results

CLI preview without `--confirm` exits nonzero and never writes. The complete deterministic token binds the exact source, canonical target, ancestors, tree, ownership, native inputs, discovery roots, consumers, and provenance. Another invocation accepts that token only while the facts remain unchanged. Empty, wrong, stale, and already-used confirmation cannot apply. The browser uses the held preview and requires typing `delete FULL_SOURCE_ID`; bare `y`, empty Enter, and Escape cannot remove content. Leaving the preview discards consent.

Apply reconstructs native discovery and exact target facts before removal. It uses anchored descriptors, no-follow child opens, parent-child identity checks, membership checks, and postorder `unlinkat`. It never runs recursive ambient-path deletion or retries newly observed names. Cancellation is checked between operations. CLI interrupt and termination signals request cancellation; a hard process kill or power loss cannot produce a final result. An advisory parent lock coordinates cooperating viewer deletion processes.

Results distinguish refused, stale, cancelled, failed, partial, and removed. Successful unlink operations retain an in-memory journal. Reinspection reports observed remaining entries, replacements, and unknown paths without following replacements. Only complete original-object accounting plus observed absence of the canonical root's original parent entry produces verified removal and exit zero. Partial removal has no rollback. Settings, remaining aliases, and references are never repaired. Running sessions may retain content already loaded into memory.

## Darwin concurrency limit

Darwin has no compare-and-unlink syscall. A same-UID writer can substitute a name after final validation or move an open directory elsewhere. Descriptor-relative traversal protects external symlink targets, but advisory locking does not exclude that writer. The guarantee covers changes observed before a syscall and normal preservation of independent sources. It does not promise atomic isolation from arbitrary hostile same-UID changes.

Held non-directory descriptors allow link-count checks after unlink, so a substituted name cannot alone establish that the original object was removed. APFS directory descriptors retain their link counts and last path after removal. Directory verification therefore combines the held descriptor's original observed path, completed guarded operations, and no-follow absence in the anchored original parent. This remains subject to the stated name-race limit. No quarantine, permission rewrite, snapshot, trash, or privileged helper changes the source before removal.
