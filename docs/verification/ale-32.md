# ALE-32 Hermes controls

Hermes global enable/disable uses the existing source-bound preview, confirmation, safe write and reinspection workflow in both CLI and terminal browser. Global means the selected active profile, not all profiles. Only that profile's `config.yaml` `skills.disabled` name membership changes. A configured external project skill remains governed by profile settings.

## Validated native contract

Reference native version is Hermes 0.20.0, clean source commit `5a16635f409e0f5e3d754bb6256bd27707bcec4c`, on macOS. Fresh contained execution of whole native `hermes_constants`, `gateway.session_context` and `agent/skill_utils.py` bodies demonstrated target inclusion in `discover_all_skill_config_vars()`, exclusion after global disable and restoration after removing the denial. Platform-denial union, shell/session platform fallback, context-local platform override and profile-home override were observed. Both project config locations were ignored by this utility. Fixture atomics model the proposed saved bytes; native CLI save/config UI was not executed.

The runner establishes an OS sandbox before imports, uses owned read/write/network/child-execution canaries, bypasses executable package initializers and records prelaunch source/interpreter/helper/policy hashes. Only selected source files, Python runtime and fixture data are readable; real settings, credentials, bundled skills and plugin trees are excluded. Source/runtime and final fixture bytes remain unchanged. Native full CLI startup, full skill index, prompt builder, explicit view, plugins, sticky startup selection, dotenv startup and live sessions were not executed. The related read rules remain pinned-source inference or the established ALE-31 bounded evidence.

The full-name native utility differs from index truncation and prompt directory-name matching. Controls therefore require consistent directory, full-content and index names of at most 64 characters, proven source identity, eligible ordinary native participation and complete known collision scope. Independent same-name sources are refused even when currently excluded or shadowed. Uncertain names, managed/plugin sources, broad plugin actions and unsupported target syntax do not produce an executable preview. Shared content is never edited.

This revision has no validated native project override mechanism. Project enable, disable and inheritance removal return `unsupported`, explain the version-specific limitation and make no filesystem change. They never fall back to global scope. Global inherit is unsupported as well.

## Persistence and effective results

Enable removes only the selected global name denial. An applicable `skills.platform_disabled` denial, source exclusion, precedence or unknown state can still prevent effective availability. Such a persisted change is reported separately from an achieved result and returns nonzero when the requested enablement was not achieved. Final inspection reuses the fresh snapshot's native control certainty for both enable and disable: newly observed policy, profile-normalization or selector uncertainty reports unknown achievement and nonzero exit while retaining committed/verified persistence and raw index evidence. Writer-only restrictions on another future edit do not invalidate an otherwise known saved native result. Running sessions may use context-local home/platform settings and caches. Adoption and whether reload/restart is necessary remain unknown.

The writer patches an admitted block YAML entry without reserializing unrelated bytes. Input and every result path, including no-ops and empty-map expansion, require a complete single-document native-compatible mapping; additional documents and trailing content are refused. The result must contain exactly the intended disabled list while preserving unrelated values. The raw profile `agent` value must be absent, null or a known mapping: native normalization can otherwise raise or silently discard profile policy during legacy root `max_turns` migration. Other shapes are conservatively unvalidated, including native-tolerated falsey values and pair lists. This admission applies to capabilities, previews, confirmations, no-ops and postimages. Harmless managed `agent` siblings merge after profile normalization and are not subject to this profile-only restriction; no provider/startup schema is inferred. A valid document-end layout that cannot be patched safely is refused without changing its markers or comments. Target aliases, merges, tags, multiline values and flow mappings are conservatively refused. Literal disabled lists, null and absent settings are supported; scalar strings remain readable but write controls refuse their cross-consumer membership ambiguity. The same admission check applies to the selected messaging-platform disabled policy, including mappings, scalar primitives and non-string list entries, before either enable or disable can write. Environment references in global or selected-platform disabled lists and in the selected name are refused without evaluating credentials. Native explicit loading expands configuration and applies managed overrides, unlike the raw utility/index policy. Managed overrides of global or selected-platform disabled policy, including null/scalar parent replacements and unknown managed inputs, therefore prevent controls; unrelated managed leaves and unselected platforms remain untouched. Unsupported explicit-key YAML layouts are rejected before byte patching, including no-op requests. Whitespace-padded selected entries never substitute for an exact-name denial when disabling. Unrelated disabled names, sibling settings and platform lists remain intact. Preview identity covers source/configuration and policy inputs; external edits, inode replacements and changes of profile, roots, policy or collisions invalidate confirmation. The shared descriptor-based writer retains permissions/ownership and verifies persisted bytes.
