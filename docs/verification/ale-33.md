# ALE-33 Pi browsing evidence

## Validated application

The recorded native application is `@earendil-works/pi-coding-agent` 1.1.0 on macOS, whose `pi --version` returned `1.1.0` on 2026-10-13. This adapter does not claim rules for older `@mariozechner` builds or other operating systems. It does not execute Pi when browsing.

Primary sources are the installed package's `dist/core/package-manager.js`, `skills.js`, `settings-manager.js`, `trust-manager.js`, and `project-trust.js`. The native receipt records their SHA-256 hashes. The [official Pi repository](https://github.com/earendil-works/pi) and its [skill documentation](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/skills.md), [resource settings](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/settings.md), and [package documentation](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/packages.md) provide context. The installed version, rather than current main, determines this implementation.

Run the reproducible native probe against an explicitly selected installed package.

```sh
python3 tests/native/pi-read-contained.py /path/to/node_modules/@earendil-works/pi-coding-agent /private/tmp/pi-evidence
```

The launcher creates a disposable outer fixture and first proves positive reads, excluded modeled system reads, denied outside writes, denied networking, denied unapproved child execution and inherited child containment. Failure stops before native imports. The OS profile allows only the owned fixture, selected Node runtime, its recorded pnpm dependency store and system runtime files, with literal ancestor metadata needed for path resolution. Live user application settings, `/etc` settings and `/Library` managed settings are excluded; their contents are not observed. The probe then creates an `ale33-native-*` disposable home and nested project inside that containment. It imports the native settings manager, package resource manager, trust resolver and skill loader. It forbids missing-package installation. It also launches the real bundled Pi CLI in RPC mode with `--offline --no-session --no-extensions --no-mcp --no-context-files --no-tools`, under the inherited strict macOS sandbox, and requests only `get_commands`. The child receives a credential-free environment. No prompt, skill workload, bundled script, extension, install or model request runs. The disposable fixture is removed after the receipt is emitted.

## Explicit limitations

The scope and relevant source explanations disclose uncertainty for ignore-file rules, complex minimatch braces and extglobs, escaped or repeated-separator glob syntax, package manifest glob expansion and filter overrides, and `autoload=false` package deltas. These cases produce native-input diagnostics rather than fabricated availability. Unsupported remote URL forms also report incomplete coverage. Managed npm legacy fallback outside the configured agent directory is not searched, and pinned remote version satisfaction is unknown. No network query or installed-package-manager subprocess is launched by the viewer.

Native `--skill`, `--no-skills`, `--approve`, `--no-approve`, SDK overrides and extension-provided resources are session-specific inputs the viewer cannot observe. The subsequent [Pi controls record](ale-34.md) owns current writer capabilities, reload evidence and remaining session limits.

A standalone Markdown file is its own source. It has no proven bundle ownership or deletion scope. It can be listed, read and explained. Existing bundle comparison reports incomplete coverage when given standalone files. It never scans or compares an entire parent directory on behalf of one file.

## Invocation identity evidence

Fresh fixture commands persist immutable invocation records immediately before CLI/PTY/tmux launch, after cwd, argv and credential-free environment are finalized. Records sample resolved executable hashes and exact inline/file policy bytes. tmux payloads record their actual shell invocation, inherited policy SHA-256 binding, shell/helper/product identities, exit status and merged terminal output. Payload recording runs inside the inherited boundary; it does not relax live-input or network restrictions. Required recording failures prevent payload execution. Final completion records hash actual output; combined-output and PTY routes put merged output in the stdout channel.

The native launcher records selected Node, sandbox executable, entry script/bundled CLI and exact profile bytes before launch. Native children bind their inherited profile to the parent's invocation record and record their finalized environment and output. Native source-closure hashes remain separate from invocation identities. Sampling at invocation is not a blanket race-free guarantee against executable replacement.

`tests/acceptance/ale33_findings_test.go` exercises the repaired traversal, canonical instruction selection, package registration shapes and BOM/newline parsing through the public executable. These topology expectations are pinned-source inference, not new native observations. Focused recorder tests use owned inert payloads and receipt artifacts, not a repeated Pi census or proof of model execution, reload or writer support. The inert Python/Node tests are recorder seams: their supplied profile bytes exercise serialization and inherited identity, not kernel containment. Ordinary CLI/PTY/tmux controls still exercise the real macOS sandbox.

Historical ordinary/native receipts without invocation identities remain historical gaps. A post-execution script digest is not an invocation-time Node, bundled CLI or profile identity. New recording does not retrofit those old launches or establish their prior effects.
