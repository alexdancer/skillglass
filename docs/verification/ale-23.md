The [README](../../README.md#build-and-use) owns current commands, discovery scope, browser controls, manifest representations, and exit semantics; this document owns inherited coverage and containment limits. ## Corrections made from executable evidence

- The first red journey failed with exit 127 because no production executable existed. The implemented vertical slice made the same public `list --root ... --json` journey pass.
- An unreadable empty root initially fabricated an unnamed source because an `Lstat` permission error was treated as proof that `SKILL.md` existed. Discovery now reports the root as incomplete and does not invent a bundle.
- The first browser frame repeated the selected-source header. The duplicate row was removed.
- The original end-of-document calculation could leave the last wrapped resource field beyond the reachable viewport. Detail pagination now reserves the actual wrapped footer height, and `G` exposes the complete last resource.
- Key help originally split words at narrow widths. Help wraps whole key-action groups at separators.
- A readable manifest inside a mode `0111` bundle was retained, but failure to enumerate its resources was initially missed. Resource discovery now handles a root `WalkDir` error before skipping the bundle directory, reports `unreadable-resource`, preserves the useful source, and exits with status 1 because coverage is incomplete.
- A directly selected bundle with directory mode `0444` could be listed but not traversed. Its failed manifest-presence probe was discarded, fabricating complete empty coverage. Successful partial enumeration now retains the same `unreadable-manifest` presence diagnostic as child candidates; a failed root listing still produces only `root-unreadable`.
- Invalid UTF-8 in instructions, frontmatter, or an unsplittable manifest was silently replaced in exported text. `TestManifestRawEncodingPreservesExactBytes` and `TestBrowserInvalidManifestEncodingHasRecoveryHint` now cover the README's lossless representation and recovery contract, with valid UTF-8, literal U+FFFD, and empty-file controls.
- YAML non-finite floats initially made JSON encoding fail after discovery. `TestNonFiniteMetadataHasTaggedJSONRepresentation` now checks the README's portable tags and diagnostic contract, nested values, raw text, and healthy siblings.
- Nested non-string mapping keys could prevent the entire JSON inventory from rendering, while top-level keys could be coerced to strings. `TestUnsupportedMetadataPreservesPartialInventory` and `TestStringKeyedMetadataKeepsNestedValues` cover rejection and supported structured-metadata controls under the README's manifest contract.
- YAML binary and alias keys could overwrite metadata, and decoded binary strings could be silently altered by JSON. `TestMetadataRepresentabilityPreservesPartialInventory` checks collisions and invalid strings, including overridden merge values; `TestMetadataRepresentabilityKeepsValidStringsAndMergeOverrides` supplies positive controls.
- Bracketed paste was ignored by the browser. `TestBrowserBracketedPasteIsSearchData` now covers filtering, pasted controls, keep/cancel/clear transitions, and ignored paste outside search.
- Overlapping roots could lose cached source diagnostics in whichever root was inspected second. Each root now counts unique diagnostics from its own references and sources, including reused sources, while global source diagnostics remain deduplicated. Informational warnings do not limit coverage.
- Long project paths and many discovery roots could consume the entire browser viewport. `TestBrowserManyRootsHasScrollableScopeAt60Columns` checks bounded headers, reachable full scope, and restoration of the inventory and scrolled detail position.
- A long search query could still wrap across the whole browser viewport. `TestBrowserLongSearchUsesSingleRowTailViewport` checks the README's search-tail behavior, full-query filtering, and editing across a resize.

## Runtime containment boundary

The Darwin acceptance harness runs public CLI, configured-root, direct PTY and tmux product payloads under `sandbox-exec`. The shared fixture policy in `tests/acceptance/fixture_policy_test.go` denies network access, real-home reads and unrelated file-content reads. Ordinary inspection routes deny filesystem writes, with only `/dev/null` and `/dev/tty` output sinks allowed. Explicit supported mutation routes permit writes only beneath the canonical disposable allowed root. Their policy also retains the historical exact `/bin/ls` allowlist entry; the product no longer launches that ACL helper (see the [shared writer metadata contract](ale-30.md)). Content allowances cover the exact product and isolation-probe binaries, the fresh fixture's allowed subtree, `/System`, `/usr/lib`, `/dev`, the literal `/` and explicit ancestor literals needed during startup. Process execution is limited to those exact binaries, plus `/bin/ls` in mutation mode. The tmux controller is a separate utility using an explicit private socket; the product payload receives no network allowance.

Known absolute native system inputs under `/Library/Application Support/ClaudeCode`, `/Library/Managed Preferences`, `/Library/Preferences/com.anthropic.claudecode.plist`, `/Library/Application Support/opencode`, `/etc/codex`, `/private/etc/codex`, `/etc/hermes`, and `/private/etc/hermes` return controlled `ENOENT`, including metadata operations. Production native roots are unchanged. Private controller-owned models verify stat/open/directory absence without inspecting live system contents. Failed sandbox compilation prevents the payload from running.

Positive controls prove that excluded canary reads, writes, loopback connections and child execution work without the policy. Contained controls require allowed fixture reads and deny excluded reads, outside/symlink writes, network access and child execution, including inherited restrictions through ordinary and tmux routes. The listener-side network observer in `tests/acceptance/network_observer_test.go` attributes traffic using a per-run child canary, independently proves allowed-child delivery, and records unrelated connections rather than treating every listener connection as a sandbox escape. Its bounded capture fails closed on errors or exhausted byte/connection caps; contained probes separately require permission-denied network errors. Invocation receipts retain executable/profile hashes, environment and cwd. The finalized launch recorder and Pi launchrecord receipts retain their distinct linked launch evidence. The finalized launch recorder captures the effective `exec.Cmd` context immediately before Run/Output or PTY start, using unique, exclusively created receipt identities. Output and exit records link to immutable launch receipts rather than recreating them after execution. Configured, absent and explicitly empty environment overrides stay distinct. Tmux product payloads use finalized argument arrays, explicit `env -i` environments and pane cwd; their receipts are separate from private utility launches. Tmux acknowledgement output/exit belongs to the utility, not an observed product exit, and links both contexts. Read-only fixture trees must remain unchanged. `TestFixtureLauncherContainmentControls` additionally exercises CLI, PTY and tmux in both modes: outside read/write canaries stay inaccessible, fixture writes match the selected mode, and owned controlled-system inputs plus inherited Codex inputs return ENOENT. Removing the expected mutation-control output restores the unchanged fixture tree. Explicit writer launch receipts record their bounded fixture-write permission rather than claiming writes are denied. The inherited isolation controls remain in `tests/acceptance/isolation_test.go`.

The ordinary CLI and mutation drivers save command results, streams and linked launch identity before reporting cancellation or launch failure. Command evidence retains the concrete `execution_error` and an `execution_canceled` flag observed at the process boundary; a context expiring after completion does not reclassify the completed exit. The finite driver budgets remain defined in the harness, not inferred product latency limits. [Driver-boundary regressions](../../tests/acceptance/ale49_driver_test.go) cover completed exits, actual cancellation and a prelaunch deadline while checking retained receipts.

This is content isolation rather than a complete macOS capability sandbox. The profile starts from `allow default`, so ambient filesystem metadata and other non-content operations remain allowed outside the explicitly denied home/system locations. Blanket metadata denial caused dynamic-loader or process-startup failures, so the metadata-absence claim is limited to the modeled locations. Controlled absence does not validate present enterprise settings or managed precedence. Earlier ordinary fixture receipts lacked this system-input boundary; historical live-content access was not established. Earlier construction-time receipts could omit finalized configured-home/cwd overrides and collapse repeated launches; the new recorder does not retroactively repair those historical artifacts or hashes.

`TestFixtureLaunchBoundary` and `TestFixtureBrowserLaunchBoundaries` also require the private excluded system model to appear absent through CLI, PTY and tmux launches. `TestFixturePolicyInertControls` retains a separate inert probe profile with ancestor directory allowances and controlled absent Codex/model inputs. The explicit offline isolation journeys use their separate `runtimeProfile` directly on the product binary; that profile does not model system inputs as absent. The native CodeAF helper has its own [runtime and build containment contract](ale-39.md#reproduce); its stronger controls must not be attributed to ordinary product acceptance.
