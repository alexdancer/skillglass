## Discovery and precedence

The explicit selected project is the only project base. CodeAF does not inherit Codex's Git ancestor walk. Each base reads direct child directories and directory aliases in this order: `.codeaf/skills`, `.agents/skills`, `.claude/skills`, `.codex/skills`, `.cursor/skills`, `.gemini/skills`, `.opencode/skills`, `.goose/skills`. Home additionally reads `.config/opencode/skills` and `.config/goose/skills`. Installed plugins follow those folders, then `.codex/skills/.system`. Ordinary roots are containers; a `SKILL.md` on the root itself does not hide child definitions or become a native skill. Nested containers are not recursively discovered.

`CODEAF_HOME` moves the discovery login base wholesale, independently of `HOME`. Without that override, discovery uses `HOME`; it is required so the viewer never silently falls back to a real login. `CODEAF_PROFILE_DIR` selects the profile and does not select skill roots. Legacy `AFORGE_HOME` and `AFORGE_PROFILE_DIR` are fallback spellings only when the new variable is empty. Profile contents are not needed or read for this journey. When project equals the login base after lexical normalization, the bases fold into one project scope, including home-only roots and both plugin scopes.

The first loaded definition owns its frontmatter name. Every project root precedes every home root. Within a base the documented root order applies; child names are sorted; plugin registry IDs sort lexically, with recorded installation/declaration order within each plugin. Plugin names stay bare, without Claude's `plugin:skill` namespace. A later independent copy is shadowed and names its winning source. A shared source retains all references and is available if one native reference wins; shadowed aliases remain explained separately. Independent copies and merely shared manifest files remain independent sources. Filters apply after availability and cannot change the winner.

The native frontmatter parser reads a regular-file head of at most 64 KiB, requires a name and description, and repairs unquoted colon descriptions before YAML parsing. Invalid names and folder mismatches are native warnings rather than exclusion; descriptions over 1,024 runes are skipped. The generic viewer retains its own stricter manifest diagnostics and complete raw content, so generic malformed status and native eligibility can differ visibly. Larger generic manifests still have the existing 4 MiB inspection limit. Broken/unreadable references stay visible. Optional missing roots are ordinary absence; unreadable selected inputs make coverage incomplete.

## Plugins and controls

Only registrations in the discovery login base's `.claude/plugins/installed_plugins.json` identify installations. Current arrays and legacy single records are supported. User installations apply globally; project/local installations require the selected canonical project. Cached folders or marketplace entries without an installation are not native sources. The viewer also inspects registered disabled installations to explain their exclusion, clearly distinguishing inspection from effective native participation.

`enabledPlugins` is read from login `.claude/settings.json`, project `.claude/settings.json`, then project `.claude/settings.local.json`. Later keys replace earlier keys; only exactly JSON `true` enables a plugin. Missing keys default off. Unreadable, invalid or oversized metadata reports incomplete coverage; such a settings layer leaves plugin permission unknown. An uncertain plugin remains a possible name competitor: a later distinct source cannot be called available or assigned a definite winner until precedence is certain. A certain ordinary route to the same source can still establish availability if no distinct possible competitor precedes it; an earlier assured winner is unaffected. Only relevant keys are exposed, never raw settings, credentials or provider data.

A plugin manifest or its marketplace entry can declare one folder or an ordered list. Declarations replace the default `skills` folder unless they name it. Marketplace catalogs resolve from known install location, conventional marketplace directory, then plugin installation; the first existing catalog wins. Absolute paths and lexical parent escapes are rejected. A declared path selects the root bundle whenever `Stat(path/SKILL.md)` succeeds, including a valid manifest link, malformed content or a nonregular manifest. If Stat fails, direct children are discovered. A broken root manifest remains an inspected source with its diagnostic and incomplete coverage, while healthy children retain native participation, plugin provenance and reachable explanations. Generic explicit roots keep their Lstat selection behavior. Registered versions remain attached to their own installation paths. Native plugin provenance is attached to the reference; managed source ownership is claimed only within the canonical installed directory. An external shared target does not become owned by the plugin merely through a link.

Ordinary imported skills do not inherit Codex disable selectors or another application's invocation policy. Winning definitions are offered automatically and through `/skill` conversation attachment in the inspected source. Existing attachments and session state are unknown. Removing an attachment does not stop later automatic discovery or model selection. A viewer refresh rereads files but does not refresh an existing CodeAF process; the native guide describes a scan at launch.

Persistent CodeAF-only per-skill enable, disable and project override are unsupported. Every source exposes explicit unsupported capability reasons through the shared JSON explanation, including plugin and shared-source consumers for later aggregate previews. Changing Claude's whole-plugin setting is a broader cross-application action. Deleting a shared source affects its other consumers. Neither operation is offered as a CodeAF-only workaround, and all writers remain unavailable.

## Reproduce

Use the pinned source revision and cached Go dependencies. The helper executes the supplied binary's `version` command after containment, so only supply an executable authorized for that invocation. For source-only validation without launching installed CodeAF, supply an inert version executable that exits 0; its identifier is not installed-build evidence. The containment regression fixture in `tests/native_verification/fixtures/version.go.txt` deliberately exits 73 and stops before source validation, so it is not a substitute for that executable. Use a fresh output directory:

```sh
python3 tools/verify_codeaf.py --source /absolute/path/to/codeaf/source --binary /absolute/path/to/approved-version-executable --output /private/tmp/codeaf-evidence
mkdir -p /private/tmp/ale-39-fixtures

env TMPDIR=/private/tmp/ale-39-fixtures GOTMPDIR=/private/tmp/ale-39-fixtures GOPROXY=off GOSUMDB=off sh tests/acceptance/run.sh /private/tmp/ale-39-acceptance
```

The native utility clears inherited environments, including Git system/global configuration and Go environment configuration. It bounds every home/profile/XDG path and working directory under `/private/tmp`. Before supplied-binary execution, it builds a trusted inert control and proves allowed fixture reads/writes plus denied outside content reads, stat, listing, symlink traversal, writes, loopback connections, separate child execution and spawning its own executable. An unavailable sandbox or failed positive/denial control stops validation. The executable is copied to private storage; its bytes and the profile digest are checked at invocation, and runtime cannot rewrite either.

Runtime and offline build/metadata policies are separate. Runtime reads only the disposable fixture and immutable executable/policy storage, observed macOS library paths, and required literal ancestor metadata/root directory handles. It denies network, writes outside the fixture, process forks, execution outside the pinned allowlist, and Mach service lookups. The build policy permits the selected Go toolchain and only the cached YAML dependency, with temporary writes; Git reads the selected source checkout under its own policy and clears real configuration fallbacks. The actual Git executable is used directly so Apple's tool-discovery shim cannot trigger installation. Build metadata is read without executing the supplied program. A version command after containment establishes only its reported identifier. Child creation is denied even when the requested child is the same allowed executable; in-process replacement by an allowed pinned image is not blocked, and retains the kernel sandbox. These controls do not establish universal process isolation or installed discovery equivalence. Copied source packages are compiled with read-only modules, CGO disabled and offline Go settings. Native receipts include version/build identifiers, source hashes, exact commands, exits, temporary paths, environment keys and explicit gaps. Source probes confirm project precedence, direct-only discovery, shared aliases, plugin settings layers, `CODEAF_HOME` discovery, and the irrelevance of profile/Codex per-skill changes to ordinary imports.
