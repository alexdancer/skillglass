# Design the terminal browsing and control workflow

Type: prototype
Status: open
Blocked by: 02, 03, 04, 05, 07, 08, 11, 12
Parent: [Skill Viewer: product direction and constraints](../map.md)

## Question

What terminal layout and interaction sequence best support finding a skill, reading it, explaining its availability in an agent and project, comparing copies, and confirming a scoped control or permanent deletion?

## Context

Use the [product brief](../product-brief.md) as the direction baseline. Produce a throwaway interaction prototype for the user to react to, not a production application. The layout, command naming, project selection, and confirmation details have not been chosen.

At minimum, walk through a shared source, independent same-name copies, a project override, a managed plugin, and a CodeAF control that is unsupported. The prototype must preserve the user's distinction between disable and permanent delete.
